# Skill do plików instrukcji podaje przy każdym werdykcie kryterium miejsca reguły i ocenia także skille

Status: ready for cycle
Project relation: independent

## Description

### Need

- Skill the way do plików instrukcji (katalog `instruction-files/` w repo the way; jego globalna kopia w setupie Mariusza nazywa się `maintain-instruction-files`) ma kryterium miejsca reguły: o miejscu decyduje to, kiedy agent jej potrzebuje — w każdej sesji, przy jednej czynności, czy za każdym razem bez wyjątku (`instruction-files/principles.md` § 2 i § 3).
- Kryterium stoi w pliku zasad liczącym ok. 3900 słów, a wiersz tabeli oceny podaje moment, w którym reguła jest potrzebna, tylko przy werdykcie „move”; przy „keep” powodem są trzy warunki sekcji 2, przy „remove” — niespełniony warunek albo wada (`instruction-files/SKILL.md:89–92`).
- Mariusz, odchudzając instrukcje, dostaje rady „skróć” bez sposobu, żeby ocenić, co ma zostać, i nie ma jak nie zgodzić się z kryterium werdyktu — tylko z samym werdyktem.
- Opis skilla wymienia do oceny tylko pliki instrukcji (`AGENTS.md`, `CLAUDE.md`, reguły; `instruction-files/SKILL.md:3`); zasady obejmują skille z nazwy (`principles.md:4`) i mówią jednym akapitem, że skill niesie procedurę, a pliki obok — dane do niej (`principles.md:122–124`), ale nie pytają, która część skilla jest potrzebna przy każdym jego użyciu, a która tylko na jednym kroku.
- Bez tej zmiany skille the way, które najwięcej kosztują w cyklu zadania, zostaną przebudowane bez wspólnego kryterium albo wcale.

### To do

1. `instruction-files/SKILL.md` podaje kryterium miejsca reguły i zasady wspólne dla więcej niż jednego rodzaju tekstu (dziś `principles.md` § 2 i § 3), a krok oceny każe przeczytać osobny plik rodzaju, który jest oceniany: plik główny ładowany w każdej sesji, skill, reguła przypięta do ścieżek plików; między plikami nie ma powtórzeń, a plik rodzaju nie odsyła do innego pliku — według odpowiedzi na pytanie o regułę wspólną dwóm rodzajom.
2. Nowa część o skillach — dla każdego skilla, także skilli procesu the way — pyta o każdy fragment skilla, czy jest potrzebny przy każdym użyciu skilla, czy tylko na jednym kroku albo w jednym wariancie; fragment z jednego kroku albo wariantu idzie do pliku obok, który ten krok każe przeczytać, a w głównej części skilla zostaje obraz całości, zasady postępowania i odsyłacze.
3. Kryterium zadaje przy każdej regule drugie pytanie: czy agent rozpozna moment, w którym reguła ma zadziałać; jeśli nie, najpierw jej warunek dostaje brzmienie rozpoznawalne w tym momencie, a reguła zostaje w całości tam, gdzie ładuje się wcześniej, dopiero gdy zapisy pracy pokażą, że agent przegapił już przeredagowany odsyłacz.
4. Każdy wiersz tabeli oceny, przy każdym werdykcie, pokazuje kryterium, na którym werdykt stoi: kiedy reguła jest potrzebna i czy agent rozpozna ten moment.
5. Opis skilla (`description` we frontmatterze `instruction-files/SKILL.md`) mówi, że skill ocenia także skille, a pliki wejściowe skilli the way (`.claude/skills/the-way-maintain-instruction-files/`, `.agents/skills/the-way-maintain-instruction-files/`) są wygenerowane na nowo poleceniem `python -B agent-instructions/skill_entry_points.py --write`.
6. Zasady skilla zastępują zdanie „Length has no threshold” wnioskiem z obu faktów: długość pliku nie ma progu, ale liczba instrukcji, które agent ma wykonać naraz, obniża, ile z nich wykonuje — i to jest powód, dla którego z głównej części skilla wychodzi to, co nie jest potrzebne na danym kroku.
7. Zasada „jeden poziom w głąb” (`principles.md:36–40`) dostaje w the way fakt o narzędziu z cytatem ze strony Anthropic „Skill authoring best practices” jako swoje źródło, a zasady podają ją jako zalecenie producenta dotyczące Claude.
8. Fakt `instruction-density-accuracy` mówi, oprócz 68% przy 500 instrukcjach, że trafność spada, gdy instrukcji naraz przybywa — słowami swojego źródła (https://arxiv.org/abs/2507.11538v1), tak jak dziś podaje to tylko `principles.md:311`.
9. Odwołania do sekcji `principles.md` spoza katalogu zasad — `instruction-files/check_instructions.py:3` i `product-guidelines/template.md:127` — wskazują po zmianie miejsce, w którym ta treść stoi.

## Decisions in play

- **WAY-128** — „A line for a file that an agent's tool loads into every session — one the skill of `instruction-files` proposes, or one a change to the-way's repository instruction files adds or rewords — is one that every session needs or that points to work an agent would not otherwise find, that an agent could not read from the repository or from general knowledge, and without which an agent would go wrong. Any other rule the skill proposes or such a change adds stands where what calls for it reaches the agent: a rule for some files in a file the tools load with those files, a rule for an activity in the steps of the skill that carries out that activity or in the file that leads it, and knowledge needed now and then in a file such a step or line points to. Lines that stand unchanged are not bound by it, and the lines of process skills and their entry points answer to WAY-35 and WAY-127 instead.”
- **WAY-35** — „An element's skill holds only the way of working particular to its element: every rule of the element's entries stands in the element's template, or once in the part the elements share (WAY-09) where it is common to them; the way of working the skills share stands once in that part, and a skill reads the rules and that way of working from there instead of restating them.”
- **WAY-127** (fragment) — „A session working on the-way itself reaches each skill of the-way as the project skill `the-way-<name>` through two identical tracked entry points, `.claude/skills/the-way-<name>/SKILL.md` and `.agents/skills/the-way-<name>/SKILL.md`, which a script of `agent-instructions` generates from the skill's `SKILL.md`. […] No global link reaches a skill of the-way other than one to `instruction-files/` […].”
- **WAY-125** (fragment) — „Each agent reads the method of its stage, and what it names, whole, while the orchestrator reads no method it does not conduct.”
- **WAY-129** — „The-way's repository instruction files hold no `@` import other than the line `@AGENTS.md` alone at the top of the root `CLAUDE.md`, and the skill of `instruction-files` proposes none other. A pointer the skill proposes, or a change to the-way's repository instruction files adds, names the file to read by its path in backticks with the condition under which to read it.”
- **WAY-130** — „The skill of `instruction-files` proposes a rule, and a change to the-way's repository instruction files adds one, only to remove a mistake agents made more than once, found in records of their work, and names that mistake where it proposes or adds the rule, unless the rule carries a decision the repository records or a step of an activity in the file that leads that activity. The skill proposes to take out a rule added for a mistake once that mistake can no longer be named, or once agents working without it show that it is not needed.”
- **WAY-133** — „Where a rule of an instruction file has to hold every time, the skill of `instruction-files` proposes a mechanism that keeps it without the agent choosing to — a CI check, a linter, a check of a step's output, or a local git hook where the rule guards against slips rather than against an agent that can turn the hook off — and a change to the-way's repository instruction files adds such a rule only with its mechanism. The instruction file then says what the mechanism is for, or carries what the mechanism cannot check.”
- **WAY-100** — „A method or practice borrowed from outside a product binds its way of working only through a decision that names what is adopted, where it applies, and why. When an agent recognizes a likeness to a method or practice no decision has adopted, it asks a human before treating it as a rule.”
- **WAY-09** (fragment) — „`instruction-files/` the principles of instruction files for coding agents, the account of how the tools load them, the skill that applies them, and the script that checks instruction files with its tests”.
