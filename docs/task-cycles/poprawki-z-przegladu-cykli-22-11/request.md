## What you will see

This change fixes the causes of fifteen problems that the agents of the earlier cycles kept writing down, so the same stumbles stop coming back. Nothing in a product changes; the work with the process changes in these ways:

- An agent that waits for a command running in the background now stops waiting after 30 minutes, whatever the product, and reports the command as unfinished with its last lines of output. The orchestrator records the check that command stood for as not run. Before, such a command could hold an agent for hours.
- A decision that narrows another can leave the decision log only after the area where it prevails has moved into the other decision or into the template or skill that takes the rule; otherwise it stays.
- A slice of a plan may leave tests red when a later slice of the same plan makes them pass, if its goal names each such test file and that slice. The orchestrator now lists those tests in the handoff of every later slice, so an executor reports such a test as failing as expected and is no longer sent back for it; a red test no goal names gets an owner by an edit of the plan.
- A slice that counts as too large only because one huge file is counted whole is now reported as fitting by the ranges of that file, and the review of the plan accepts it.
- The check of instruction files gives much less noise: text that is no path (addresses in an app, text in quotation marks, a bare file extension, a list or an assignment) is not looked up; a path on another machine is noted, not reported as missing; a path under a name the repository's ignore file gives is noted too. A warning is now fixed like an error, and a warning in a run on the head of a change blocks the review of the whole change.
- A fresh copy of a repository that an agent makes to run checks gets the-way and the dependencies installed first. A page kept in the web archive as a source must hold the quoted passage, and the entry says so when it does not. A dependency between parts that a task asks for is written into the part map by the change. A test that holds a sentence of a decision carries the line that names it, one line for each decision; and the checks run after the new files are added to git.
- The script that lists decisions now finds a decision by the value of its number (written with a prefix, with a leading zero or bare, it is one decision) and, for a withdrawn number, names the successors, or says that it has none, instead of ending with an error. The measuring of the gate now starts `npm` on Windows, and the count of the tests of a directory is the last count its output gives. ## Co zobaczysz

Ta zmiana poprawia przyczyny piętnastu kłopotów, które agenci z poprzednich cykli zapisywali raz po raz, żeby te same potknięcia przestały wracać. W produktach nic się nie zmienia; zmienia się praca z procesem:

- Agent, który czeka na polecenie puszczone w tle, przestaje czekać po 30 minutach, w każdym produkcie, i zgłasza polecenie jako niezakończone z ostatnimi liniami wydruku. Prowadzący zapisuje sprawdzenie, za które to polecenie stało, jako niewykonane. Dotąd takie polecenie mogło trzymać agenta godzinami.
- Decyzja, która zawęża inną, może opuścić dziennik decyzji dopiero po przeniesieniu obszaru jej przewagi do tamtej decyzji albo do szablonu lub skillu, który przejmuje regułę; inaczej zostaje.
- Kawałek planu może zostawić czerwone testy, które naprawia późniejszy kawałek tego samego planu, jeśli jego cel nazywa każdy taki plik testów i ten kawałek. Prowadzący wypisuje te testy w zleceniu każdego późniejszego kawałka, więc wykonawca zgłasza taki test jako czerwony zgodnie z oczekiwaniem i nie jest odsyłany; czerwony test, którego żaden cel nie nazywa, dostaje właściciela przez zmianę planu.
- Kawałek, który wychodzi „za duży” tylko dlatego, że jeden ogromny plik liczy się w całości, jest teraz zgłaszany jako mieszczący się po zakresach tego pliku, a przegląd planu go przyjmuje.
- Sprawdzarka plików instrukcji daje dużo mniej szumu: tekst, który nie jest ścieżką (adresy w aplikacji, tekst w cudzysłowie, samo rozszerzenie, lista czy przypisanie), nie jest wyszukiwany; ścieżka na innej maszynie jest odnotowana, a nie zgłoszona jako brakująca; ścieżka pod nazwą z pliku ignorowania repozytorium też jest tylko odnotowana. Ostrzeżenie naprawia się jak błąd, a ostrzeżenie w przebiegu na głowie zmiany blokuje przegląd całej zmiany.
- Świeża kopia repozytorium, którą agent robi, żeby puścić sprawdzenia, dostaje najpierw the-way i zależności. Strona zachowana w archiwum internetu jako źródło musi zawierać cytowany fragment, a wpis mówi, gdy go nie ma. Zależność między częściami, o którą prosi zadanie, zmiana wpisuje do mapy części. Test, który trzyma zdanie decyzji, nosi linię z jej numerem, po jednej na decyzję; a sprawdzenia puszcza się po dodaniu nowych plików do gita.
- Skrypt listy decyzji znajduje decyzję po wartości numeru (z przedrostkiem, z zerem na początku albo samą liczbą to jedna decyzja), a dla numeru wycofanego wymienia następców albo mówi, że ich nie ma, zamiast kończyć się błędem. Pomiar bramki uruchamia `npm` na Windows, a liczba testów katalogu to ostatnia liczba z jego wydruku. Próba, która pokazuje uwagę recenzenta, zostaje obok raportu, a sprawdzenie szukające zdania prozy znajduje je także na złamaniu linii.
