### I-2. Slice 7 (`8ef214d`): the report-order test lost its margin and races. Comes from slice 7.

- Place: `gate/test_run_tests.py:386-397` (`test_each_report_stands_whole_under_its_own_line_in_the_order_directories_end`), `timed_module(log, "a", ["end b"], lines=4)` with no pause; helper `timed_module` at `gate/test_run_tests.py:38-77`.
- What is wrong: the base held directory `a` running two seconds after it saw `end b` (`pause=2.0`), so `b`'s report always printed first. Now `a` ends as soon as it sees `end b` — a poll of 0.02 s after `b` wrote it, and `b` writes it as the last thing before it exits — so which process the runner sees end first is decided by milliseconds of process teardown. This is the clock-and-load dependence that cause 4 of the task (item 15) exists to remove; the slice replaced a long pause with a race that is shorter by three orders of magnitude, and its own report names it as the "residual race" (executor-7-report, *Concerns and questions* 2) and did not close it.
- Failure scenario: on a loaded machine or in CI the order flips and the test fails with `["a", "b"] != ["b", "a"]` on unchanged code; WAY-243 and the task's own wording ("a red gate without a cause costs every cycle that meets it").
- Evidence: 40 runs of this one test in a worktree of the base: 0 failures; the same test at the head: 1 failure in 40 and 1 in 60 (while other suites ran on the machine). The executor's own suggestion closes it: let `timed_module` write an event when its process is ending and have `a` wait for that event (or release `a` from the driver after `b`'s report has been printed).
