## D3 — Author evidence and reviewer independence

Proposed section: pass the styleguide's plan-order example to the planner or no-plan author explicitly as an example. Before review each UI author/slice executor checks the states the product's applicable styleguide requires for affected components, honoring stated exceptions/departures, alongside the existing weakest-point check. Use the product foundation's interface route to inspect a screenshot, naming what was inspected, observed result and evidence path in the report. Where the foundation settles no route, check states from code and report the screenshot unchecked with that reason in both stage report and request. Do not invent an access route, require visual regression baselines or claim code inspection proves rendered focus. A settled route that fails is an actual failed/unperformed check with evidence, not the no-route exception. The review handoff carries generic criteria: grade a visual finding by its concrete user-visible consequence; a difference from a guideline example or unscripted part of an exemplar alone cannot justify a blocking finding, which needs a named user/correctness consequence. No existing finding is preclassified, and the reviewer alone chooses grade/scope under WAY-161/162. The independent foundation assessor's filtered input contract remains unchanged; it finds pertinent guidelines through allowed repository files, never an operational handoff or checklist.

Alternatives/costs: prespecifying Important for all appearance findings violates independent grading and can block polish; leaving severity unqualified permits visual faults to be dismissed as style. Requiring screenshots with no settled route contradicts the accepted no-route fallback; making code inspection count as visual evidence conceals the gap. Recommended generic criteria preserve grade ownership but still depend on reviewer judgment; screenshots cost author work only on UI changes, and the permitted no-route gap remains visible.
