## What you will see

When a project plan is written, the author now has a test for a task that is too big: a task is too big when its goal joins two or more results, each of which could be checked alone in the running product and merged before the others. A task that gathers clearly more of the definition's open questions, projected entries or scope items than the rest of the plan is only a signal to look at it; no number decides it. The independent critique of the plan is now asked to judge the size of every task by that test, and the author hands the critic the test's text with the request.

A task the critique calls too big is no longer split by the plan's author. It reaches you as a question before the plan is handed over, with the proposed split and the choice to keep the task as it is, so that you decide whether an extra cycle is worth it. Applied to the old account task of the first game plan (accounts, login, blocking, address confirmation, password reset and mail), the test marks it too big; applied to "the owner blocks a player's account, and the blocked player loses the session and cannot log in", it does not.

## Co zobaczysz

Gdy powstaje plan projektu, jego autor ma teraz test na zadanie zbyt duże: zadanie jest za duże, gdy jego cel łączy dwa albo więcej wyników, z których każdy da się osobno sprawdzić w działającym produkcie i scalić przed pozostałymi.
