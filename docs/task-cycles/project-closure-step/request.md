## What you will see

When the last task of a project's plan is done, the agent that leads the plan no longer says "there is no closing step" and stops. It now closes the project with you, in a fixed order:

- It first checks that every task of the plan is done, delivered by another task, or dropped. If a task is still in a cycle or ready for one, it tells you which task and in which state, and does not start. A task marked as delivered by a task that was dropped holds the closing the same way, since nobody made that work.
- For each dropped task you choose one of three places: the note of the next project, a task of its own, or given up for good with a reason you give. The closing carries the task's goal, the plan's open questions that point at it, and the foundation entry the task was to write and did not, to that place. Where the next project already has a note, it adds a section to that note instead of making a second file; where a task already has a line or a section, it completes it and makes no second one.
- To tell whether such an entry exists, it searches the product's foundation at a named commit, by the entry's question, identifier or term, and writes "absent at commit X" or names the entry it found, a part of one included. A match it cannot be sure of goes to you as a question, and a change to a current entry whose text does not hold the change is not counted as found.
- It then shows you the whole of what it will write: the closing item for the plan's change log (how many tasks are done, delivered by another task and dropped, where each dropped task went, which "In scope" items of the definition no finished task delivered, and which entries the dropped tasks did not write), the change of the plan's status to `closed <date>`, and the full text of each move. It writes only after you accept all of it.
- The plan's status line can now read `closed YYYY-MM-DD`. The plan check refuses a closed plan with a task in any other state, and a closed plan whose "delivered by another task" row points at a dropped task. The reader of a plan's state says plainly that the plan is closed, where before it failed for want of "handed over". The skill that leads the plan, meeting a closed plan, says so and stops.
- The definition of the project is never changed. Where what was delivered differs from it, only the closing item says so.

### Underneath

The closing is described in one new file beside the skill that leads the plan, read only when the step comes; the plan template, the plan check and the state reader know the new state; the foundation records six settlements of the task as five decisions, a sentence added to one rule of the plan check, and the edit of one decision.

## Co zobaczysz

Gdy ostatnie zadanie planu projektu jest zrobione, agent prowadzący plan nie mówi już „nie ma kroku zamknięcia” i nie staje. Zamyka projekt z Tobą, w stałym porządku:

- Dla każdego zadania porzuconego wybierasz jedno z trzech miejsc: notatkę następnego projektu, samodzielne zadanie albo porzucenie na zawsze z podanym przez Ciebie powodem. - Żeby ustalić, czy taki wpis istnieje, szuka w fundamencie produktu na wskazanym commicie, po pytaniu, identyfikatorze albo terminie wpisu, i pisze „brak na commicie X” albo wskazuje znaleziony wpis, także częściowy.
