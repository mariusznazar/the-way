## What you will see

Three small changes to how work with the process reads, each at a place where an agent or you lost a step.

First, in the description of a request. Where the cycle could not run a check and you can do it by hand — for example open a page in a running copy of the product — the item that asks what to do with it now also gives three to six steps for the check: where to go, what to do and what you should see. The item's three answers stay the three they are (do it in this request, make a task of it, let it through), and after checking you write a remark as before. The agent that writes the description reads each such item for the steps before the request opens. An item for a check you cannot do by hand has no steps.

Second, in the task document and in the skill that refines tasks. A place to change in a file is pointed at by its heading or a quotation from it, and a line number is only a hint, since lines move. The source under a question's answer stays as it is, with the line and the revision, because that line is read at that revision.

Third, in the review of the foundation. The review now lists the decisions that describe a transitional state of the product — a state such as "for now both versions exist", which a later piece of work is to end — and asks you, at each, whether a task exists that ends it. Where none exists, it proposes creating one, as it does for its other proposals, and you decide. The review counts as done only when you have answered for each such decision. A decision's entry gets no field for the task.
