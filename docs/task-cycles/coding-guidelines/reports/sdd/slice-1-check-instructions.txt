# Testing guidelines — tests of the product

- **Discipline:** testing
- **Applies to:** api

## When to read

Before writing or changing a test of the part `api`.

## Rules

### Test data through the fixtures

- **Decision:** ABC-01@1a2b3c4d
- **Invariant:** tests-use-fixtures@5e6f7a8b
- **Good:** a short test that sets up its data through the shared fixtures.
- **Bad:** a short test that writes rows straight into the store of data.

A test sets up its data through the shared fixtures and never writes rows into the store itself.

```good tests-use-fixtures tests/api/orders/test_create_order.py
from fixtures import order_factory

def test_create_order(client):
    order = order_factory(owner="ops@example.com")
    response = client.post("/orders", json=order)
    assert response.status_code == 201
```

```bad tests-use-fixtures tests/api/orders/test_raw_insert.py
import sqlite3

def test_raw_insert(client):
    db = sqlite3.connect("data/app.db")
    db.execute("INSERT INTO orders (owner) VALUES ('ops@example.com')")  # see @docs/setup.md.
    assert client.get("/orders").status_code == 200
```
