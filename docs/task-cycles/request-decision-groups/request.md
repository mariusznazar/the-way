## What you will see

From now on the part of a request's description that asks for your decision is cut into three groups, always in the same order, each under its own heading. *Needed from you* holds what blocks the request until you answer or act. *Fix or let through* holds something the cycle did not do or did not fix and that can still be done in this request; for each such item you choose between doing it now, making a task of it, or letting it through. *You accept by merging* holds what the cycle did within its authority; merging is your agreement, nothing in that group waits for a separate answer, and the group opens with a sentence saying so. A group with nothing in it reads `none`, and when all three are empty the whole section reads `none` alone. The items are numbered in one run through the three groups.

An item in which you choose now has to say what happens and who will feel it, what each way costs, what the writer recommends and why, and then ask one question with the answers to choose from. The agent that writes the description checks every such item against these four things before the request opens, so that an item like "the return step was skipped; merge without it?" no longer reaches you.

### Underneath

The template of the description, the script that checks the form of the description, the two skill files that point at the template, and four decisions of the process changed; one new decision says what an item in which you choose must carry.
