# Glossary

The words of the process, each in one meaning: every word that means in the-way something other than
a reader who knows the field takes it to mean.
A product takes these words from the-way at the commit it pins (WAY-95).

## agent's way to the running product

An agent's way to the running product is the means through which an agent checks behaviour a user sees in a product while it runs.

- **Not:** none

## binding part

A binding part is the text of an entry that whatever relies on the entry, rather than only mentioning it, depends on.

- **Not:** none

## binding sentence

A binding sentence is a sentence of a binding part.

- **Not:** none

## critical flow

A critical flow is something a product does end to end across several of its parts, singled out as one to keep working.

- **Not:** none

## debt

Debt is a breach of a rule a product's foundation holds, or such breaches taken together.

- **Not:** none

## element

An element is a division of a product's foundation that holds entries of its own kinds.

- **Not:** none

## entry

An entry is the text, under one or more headings of its own, that a file of the foundation holds about one thing it records.

- **Not:** none

## environment fact

An environment fact is something a product takes as true about the world around it that, unlike an invariant, no commit of the product makes true or false.

- **Not:** none

## foundation

A product's foundation is the written record of the rules the product holds itself to, of what those rules stand on and of where the product breaks them.

- **Not:** the files of `foundations/` taken together with the templates of the elements — "elements' templates"

## foundation step

The foundation step is the step of a task in which the task writes the change of the foundation it sets out to make, as against what its return step carries back.

- **Not:** none

## gate

The gate is the one command that runs all of a product's tests, the tests of its invariants among them.

- **Not:** none

## guidelines

Guidelines are text a product keeps outside its foundation that tells agents what to do and how in a discipline of work on the product.

- **Not:** none

## human action

A human action is an act outside the product's repository that a task needs and a human performs.

- **Not:** none

## invariant

An invariant is a sentence about the product that is true or false on every commit.

- **Not:** none

## invariant test

An invariant test is a file that holds a check citing an invariant, or a file such a check reads and names as its data.

- **Not:** none

## open design choice

An open design choice is a choice that neither a task's document nor a spec written for the task settles and that either sets a foundation entry or takes a way that is costly to turn back once code is written on it, as against a choice of how to make what is already settled.

- **Not:** none

## part

A part is a piece of a product with a responsibility of its own.

- **Not:** none

## part map

The part map is the element of a product's foundation that sets out the product's parts and what joins them.

- **Not:** none

## preparatory task

A preparatory task is a task of a project plan whose end shows nothing in the running product.

- **Not:** none

## read off

A value is read off when it is what a tool gives from the product or the machine as they stand, whoever writes it down.

- **Not:** none

## repository instruction file

A repository instruction file is an instruction file for coding agents that a repository's git tracks under the name `AGENTS.md`, `CLAUDE.md` or `CLAUDE.local.md` in any of its directories, `.claude/` among them, or as a Markdown file its root `AGENTS.md` or `CLAUDE.md` names by its path.

- **Not:** none

## return step

The return step is the step of a task that carries back to the foundation what the task's change holds and the foundation does not yet say.

- **Not:** none

## slice

A slice is a piece of a task's change that the task's plan sets apart with its own files, goal, material to read and checks.

- **Not:** none

## surface

A surface is something of a product that someone outside the product relies on and that the product promises to keep.

- **Not:** none

## user interface

A user interface is a set of screens that a product draws and through which a person uses it.

- **Not:** none

## project orchestrator

A project orchestrator is the agent that leads a handed-over project plan in conversation with the human.

- **Not:** none

## exemplar

An exemplar is a file of a product that a decision of the product designates as the model after which later code of its kind is written.

- **Not:** none

## standing check

A standing check is a check that a tool makes of every change to a product's code for the whole of the product, rather than for one kind of code, as a linter, a formatter or an audit of dependencies does.

- **Not:** none
