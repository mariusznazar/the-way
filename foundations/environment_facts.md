## git-path-patterns

Git matches a path pattern of an attributes file by the rules of `.gitignore` patterns, except that a negative pattern is forbidden and a pattern that matches a directory does not match the paths inside it.

- **Source:** https://git-scm.com/docs/gitattributes/2.55.0 § DESCRIPTION — "The rules by which the pattern matches paths are the same as in .gitignore files (see gitignore[5]), with a few exceptions:" · § DESCRIPTION — "negative patterns are forbidden" · § DESCRIPTION — "patterns that match a directory do not recursively match paths inside that directory (so using the trailing-slash path/ syntax is pointless in an attributes file; use path/** instead)"; read 2026-09-26

## sha-256

The Secure Hash Standard specifies SHA-256, whose final output is a 256-bit message digest, in its section 6.2.

- **Source:** https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf § 6.2 — "The final result of SHA-256 is a 256-bit message digest."; read 2026-09-26

## utf-8

UTF-8 encodes every character of the range U+0000..U+10FFFF in a sequence of one to four octets.

- **Source:** https://www.rfc-editor.org/rfc/rfc3629.html § 3 — "In UTF-8, characters from the U+0000..U+10FFFF range (the UTF-16 accessible range) are encoded using sequences of 1 to 4 octets."; read 2026-09-26

## python-stdlib-modules

## impossiblebench-test-modification

## impossiblebench-cheating-strategies

ImpossibleBench identifies four cheating strategies of models facing impossible tasks — modifying the test cases, overloading comparison operators, recording extra states and special-casing — and reports that the latter three show that models can work around instructions not to modify tests while technically complying with them.

- **Source:** https://arxiv.org/html/2510.20270v1 § 3.1 — "We perform our experiments on a suite of leading open-source and closed-source models: GPT-5, o3, o4-mini, GPT-4.1, Claude Opus 4.1, Claude Sonnet 4, Claude Sonnet 3.7, and Qwen3-Coder." · § 4.1 — "Analyzing the transcripts, we identify four distinct cheating strategies that models employ when faced with impossible tasks, ranging from direct test manipulation to sophisticated state-based exploits." · § 4.1 — "The latter three strategies are especially concerning, as they demonstrate that models can devise creative workarounds even when they technically comply with instructions not to modify tests." · § 4.1 — "Modify Test Cases: The model directly modifies tests despite being explicitly instructed not to." · § 4.1 — "Overload Comparison Operators: The model overloads the comparison operators so they always return desired values." · § 4.1 — "Record Extra States: The model records extra states in order to obtain different results for the same input." · § 4.1 — "Special Casing: The model special-cases the test cases to pass them."; read 2026-11-16
