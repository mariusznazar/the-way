# Starting rules

The styleguide of a user interface comes into being before that user interface's first screen. A
first screen built with no rules is the screen every later one copies.

For the first styleguide, with or without screens, and at every refresh or extension:

- Ask, as one question of assessment, for the human's preferences for styling in the technology of
  the user interface that the product's foundation settles; "I do not know" is an answer. A tool
  the human prefers is the one proposed, and no other is offered in its place.
- For the first styleguide where the human has no preference, and at every extension, research the
  basic rules for that technology: read `research.md` beside this skill. At a refresh, do no
  research and use the accepted styleguide with the update or correction the task calls for.
  Research with sources keeps the quality of the rules where a fixed list in the-way would fit no
  technology well, and a refresh needs none, since correcting accepted rules within their scope
  needs no new comparison.
- Add the product's own meanings: from its definition, plan, specs and mockups, describe each
  screen the product announces — what the user sees, the components it is built from, and its
  states with the messages the user reads. A mockup shows what a screen holds; the meaning of a
  colour on it is settled with the human, never read off it (WAY-174).
- The starting set covers the roles, states and focus the announced screens need, so it is wider
  than the first task that uses it.
