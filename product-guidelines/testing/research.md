# Research of the starting set

Split research into the questions the starting set or the scope being added must answer there —
how the product's test tool lays out and names the tests of each level, what it offers in place of
a real dependency, how a test is given the clock and the seed it runs with — and give each to a
fresh agent of its own, all at once, with the technology, the preferences, the scope being added
where this is an extension, and the binding sentences of the decisions that settle it. Include any
new tool's consequences for the product. Each source is a page with its version, never memory and
never a fixed list; each report goes to `.runs/testing/<question>.md`, the question's name in lower
case with hyphens.

Once the reports are in, give one fresh agent, following `critique`, each report with its sources,
and ask it to refute every claim no source supports — a convention of the tool, a rule, a
difference between ways of testing. Before the first critique of the session, read
`elements/common/critique/SKILL.md`. Verify each observation and give your verdict, correct the
report by the verdicts, then end it with the line `critique: passed`. Where no fresh agent can run,
the research does not go on: stop and say so (WAY-249, WAY-120). What the research finds is
proposed in step 4, never imposed.
