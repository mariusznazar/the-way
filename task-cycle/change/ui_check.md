# Checking a changed user interface

What the own-work check adds when a change alters what a screen shows.

- Changing a user interface, check the states of the affected components that the applicable
  styleguide requires, and inspect a screenshot of the running product by the route its foundation
  settles; where it settles none, check the states in code and mark the screenshot unchecked with
  that reason (WAY-219). Where the settled route fails, report the failed or unperformed check
  itself, not the missing-route reason. Reading code shows no rendered appearance.
- A screenshot you show the human lies in the place the product's foundation settles for screenshots,
  outside the product's repository, never in a file of the repository or of the cycle's record, and
  your report names where it lies, so that the request can embed it as an image (WAY-316). Where the
  foundation settles no such place, you still inspect the screenshot but keep none, and your report
  says that no place is settled, so that the request tells the human (WAY-317). Of the artifacts of
  the check only screenshots are shown; describe motion in words, and keep logs and outputs in the
  report (WAY-318). The file the screenshot tool writes by itself is a working copy: move it
  to that place, or where none is settled into your directory for working copies, and remove the
  original; the file in your directory goes before you return, as the dispatch's paragraph on
  working copies gives.
- Check through a way that does not share a browser with another cycle, and close the browser you
  opened when the check ends (WAY-319).
